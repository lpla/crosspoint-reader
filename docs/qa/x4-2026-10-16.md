# X4 physical test record, 16 October 2026

Automated tests on a USB-connected physical Xteink X4 (ESP32-C3 revision 0.4,
16 MiB flash, no PSRAM). These are not desktop-simulator or QEMU results.
No photograph or optical-panel validation is claimed. Private EPUBs, raw logs,
network credentials and flash backups are deliberately excluded.

## Instrumentation

Absolute heap observations used release firmware without the local USB QA
controller. Standard serial memory logs remained enabled; screenshots were
requested after the observation interval. These are USB-attached readings,
not unplugged battery-life or wake-time measurements.

With the local controller disabled, a reproducible same-path, same-profile
comparison found every allocated ELF section identical to vanilla: address,
size, flags, type and contents, including initialization arrays. The flash
image differs in standard ELF-hash metadata and dependent checksum/digest,
so whole images are not byte-identical.

Enabled local QA adds 232 B BSS and 1,632 B application image in the matched
development-profile comparison; alignment moves the heap start by 224 B.
Polling and input sampling add CPU work. A long Arduino printf reply can
temporarily allocate. There is no extra framebuffer or task. Those costs
belong to the local prototype, NOT to PR 3510's different implementation.
No numeric subtraction can undo fragmentation or allocation-threshold effects.

Input-driven tests below are instrumented functional/stress evidence. Each
navigation input waited for reader render completion. They are not absolute
release benchmarks, and host wait time is not rendering time. Page layouts and
full-refresh cadence differ, preventing a general speed comparison.

## EPUB styling: PR 3891 and explicit inheritance

Tested head: `bbfd23489f832700830db57b5388a38e9cf88df0`.
SDK pin/checkout: `32a265fa86498c014e13a5bc16133bb021cb620c`.
The comparison is this PR versus this PR plus the narrow explicit-inheritance
patch, NOT develop versus the whole rendering PR. Later PR commits are untested.
The patch preserves `font-weight: inherit` / `font-style: inherit` through the
cascade and resolves them from the parent. Explicit normal still resets them.

Same original book bytes and matched settings within each comparison:
Noto Serif 18, portrait, antialiasing and embedded styles enabled, hyphenation
disabled. Test-book caches were cleared between cold baseline/candidate runs.
There was one cold release run per book/build, not a repeated statistical sample.

| Book / spine | Variant | Free bytes | Minimum since boot | Largest block |
| --- | --- | ---: | ---: | ---: |
| Las hijas horribles / 7 | PR baseline | 109252 | 84420 | 102388 |
| Same | With inheritance patch | 101084 | 75304 | 90100 |
| Proyecto Hail Mary / 8 | PR baseline | 107248 | 87532 | 102388 |
| Same | With inheritance patch | 99576 | 76576 | 90100 |

No OOM, panic or CSS low-heap fallback occurred in these bounded sessions.
Physical complete-cache readbacks had 65 unique styles each: 180 rules for
Hijas, 207 for Hail Mary. `sizeof(CssStyle)` remains 128 B. Distinguishing
inherit from normal crosses the existing 64-to-128 capacity boundary in these
books: 8 KiB extra retained style bodies, NOT 8 KiB remaining RAM. Old and new
style arrays coexist during growth, totalling 24 KiB excluding allocator cost.

Four additional instrumented cached-CSS runs (two books, two variants) completed
20 turns each: 10 forward and 10 back, 80 total. No OOM, panic or low-heap CSS
fallback was observed. The since-boot minima in those runs also include Home
setup and must not be presented as isolated CSS peaks.

Source checks on the tested inheritance candidate: 87 chapter-parser and 28
CSS-parser tests passed. Unsupported GIF messages in Hail Mary are expected
because this isolated rendering build does not include PR 2299.

## GIF: PR 2299

Head: `eed83542d847eb1d6771d66e801fa7108b58ea7b`.
SDK: `425d200a8ea447326b4b9696e4e47dc84ad9d7f6`.

A locally generated, original six-spine fixture exercised:

- 2495 x 200 static GIF, scaled to 464 x 37.
- 320 x 200 transparent GIF.
- Two-frame animation, using the first frame only; second-frame pixels differ.
- Interlaced GIF, explicitly rejected as unsupported.
- Width 3073, above the 3072 limit, explicitly rejected.
- Truncated global colour table, rejected as malformed.

The exact original test file is [gif-cases.epub](fixtures/gif-cases.epub).
Copy it to SD, open it from the file browser, read through all six sections and
back, then reopen and repeat. The final three cases should omit their images
without rebooting; only the first three should create pixel caches. The fixture
contains generated stripes and test text, not third-party artwork or book text.

Ten cold and ten warm turns completed without OOM or panic. Normal File Transfer
readbacks verified exactly three valid pixel caches with consistent dimensions
and payload lengths: 4296 B, 16004 B and 16004 B. No partial pixel caches existed
for the rejected cases. Logs showed cache reuse during the return trip.
Settled warm free heap was 139932 B, largest block 114676 B. This does not prove
all GIFs safe or validate optical transparency on the physical panel.

## Table grids: PR 2954

Head: `4242953183763d6e68787d67ec7b4a75a792155e`.
SDK: `7fcd3b34c108f28c086ade3b433924022dbc0998`.

The repository's table-edge-case EPUB was tested in LTR mode. Six cold turns,
six warm turns and a 20-turn extension completed (32 total). Close/reopen loaded
a suspended ten-page partial cache, resumed the build through page 23 and
returned to spine 1/page 0. No cache-load failure, OOM or unexpected reset was
observed. The final settled free heap was 139100 B, largest block 98292 B.
RTL layout and optical border quality were not covered by this run.

## Hyphenation manager: PR 3706

Head: `3749a26209a2d6d48a03b4d07015ba6e63e71a52`.
SDK: `7fcd3b34c108f28c086ade3b433924022dbc0998`.

An original synthetic Catalan EPUB opened with hyphenation enabled and no pack.
The missing-pack prompt led to the manager. Saved-network connection, the
6366-byte production manifest and a Spanish pack downloaded over HTTPS.
The UI marked Spanish installed; cancelling the manager returned to the book.

Next, the official Catalan pack was uploaded to `/hyph-ca.cphyph` via normal
File Transfer. Entering the manager consumed it and intentionally restarted
straight into the same book. The missing-pack prompt disappeared. Twenty
completion-checked page turns passed without an unexpected reset or OOM.
Flash-bank header and payload CRCs were checked independently; the version-59
partial section header's pattern identity matched the Catalan payload CRC.

The HTTPS workflow reached 22040 B minimum free heap. After cancelling the
online manager, free heap recovered but the largest block remained 36852 B;
this is an observation, not proof of a defect. After SD import/restart the
largest block recovered to 114676 B. X3, German before/after render timings,
oversized-manifest fault injection and interrupted flash writes were NOT tested.

## Cleanup, exclusions and remaining checks

The original settings/state/recents and the full 3538944-byte SPIFFS partition
were restored byte-for-byte, verified by readback. Test books, test caches and
staged packs were removed. NVS was not overwritten; normal Wi-Fi metadata or
derived library caches may have changed. The device was left running the local
QA-enabled inheritance candidate, not normal develop-lpla.

Aggregate valid input-driven coverage: 152 page turns. An earlier Home-only
navigation attempt and a fixed-cadence attempt were excluded, then rerun with
reader/render-completion checks. A 20-second screenshot timeout was retained
as a failed capture, never accepted as a complete image. The local client now
uses a bounded 120-second capture timeout with a regression test.

Boot-key snapshot/routing bugs found in that local QA prototype were corrected
and reviewed; they were not reproduced in PR 3510 and are not attributed to it.
No physical test is claimed for PR 2643 or the rest of the maintainer queue.
Physical boot/recovery key combinations, remote/physical overlap, four-way
remapping, cable-unplug termination and optical panel checks remain human work.
